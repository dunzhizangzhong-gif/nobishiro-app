# /step3-review — 独立AIレビュー(必ず別モデル・別セッションで実行)

あなたは独立したモバイルアプリ仕様レビュー担当です。
specs/spec.md を実装せずに監査してください。
次の観点で、重大度 Blocker / Major / Minor に分類し、
該当する仕様ID・不足内容・修正案を表で出してください。

1. ユーザー価値と競合との差別化
2. 仕様の曖昧さ・矛盾・対象外の不足
3. 受け入れ条件(AC)がテスト可能な形式か(自動テストに変換可能か)
4. データ、権限、エラー、オフライン、削除、課金の抜け
5. App Store審査ガイドライン 4.1(オリジナリティ)、4.2(最低限の機能)、
   4.3(スパム・類似)、5.1(プライバシー)、2.5.2(未審査コードの実行)に関わる懸念
6. 実装規模がMVPに収まるか

新機能を勝手に追加しないでください。
Blockerが1件でもあれば「実装開始不可」と明記してください。
