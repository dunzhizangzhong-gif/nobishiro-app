# /step2-spec — 仕様書作成(Fable 5セッションで実行)

specs/research.md(特に末尾のSTEP 1材料メモ)を読んでください。

このアプリをSpec-Driven Development方式で計画します。
まず、仕様を固めるために最も重要な確認質問だけをしてください
(3〜5個まで、些細な質問は仮定で埋めて構いません)。往復は1回だけです。

回答を得たら、以下10項目からなる仕様書を specs/spec.md に作成してください:
1. 目的・プロダクトビジョン
2. 対象ユーザー
3. 主要な利用の流れ
4. 核となる機能
5. 今回やらないこと(対象外の範囲)
6. 技術的な前提・制約(CLAUDE.mdの固定スタックに従う)
7. データ構造(案)
8. 画面構成
9. 受け入れ条件(AC)
   AC-001形式のID、Given/When/Then形式。各ACに優先度(Must/Should/Nice)、前提データ、
   期待結果、失敗時の挙動、テスト種別(unit/integration/E2E/手動)を付ける。
   「使いやすい」「適切に」「素早く」等の判定不能な表現は禁止。
   成功指標の計測(STEP 7で使うイベント記録)もACに含めること。
10. リリースDefinition of Done
    AC全件Pass、必須自動テストPass、実機スモークPass、クラッシュなし、
    プライバシー申告との整合、審査用情報完備、ライセンス確認済み、既知不具合の記録・承認
